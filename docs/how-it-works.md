# 足跡ジャーナルはどうやって作業を推定しているか

足跡ジャーナルは、画面の中身やキー入力を読んでいるわけではありません。記録しているのは「いつ、どのウィンドウが前面にあったか」などの**手がかり**だけです。AI はその手がかりを時系列に並べたものを読み、「何をしていたか」を推定しています。

この文書では、次の 3 段階を順に説明します。

1. **記録**: PC から何を集めているか
2. **要約**: 集めたものを、AI に渡すテキストへどう変換しているか
3. **推定**: AI に何をどう判断させているか

あわせて、推定を外しやすい場面とその対策も書いています。

```
 PC の様子 ──(1) 記録──▶ 日ごとの記録ファイル ──(2) 要約──▶ タイムラインのテキスト ──(3) 推定──▶ 作業ブロック・日報・回答
```

---

## 1. 記録: 何を集めているか

記録は `%LOCALAPPDATA%\Ashiato\journal\YYYY-MM-DD.jsonl` に 1 行 1 件で保存されます。中身はテキストなので、メモ帳でも開けます。

| 種類 | 記録する内容 | 取り方 |
|---|---|---|
| ウィンドウ | 前面にあったアプリ名とウィンドウタイトル、その開始・終了時刻 | 数秒おき（既定 5 秒）に前面ウィンドウを確認し、変わったら区切る |
| 無操作 | キーボード・マウスの入力がなかった時間 | 一定時間（既定 5 分）入力がないと「無操作」とする |
| 画面ロック | 画面ロック・スリープしていた時間 | Windows のロック・スリープ通知 |
| 会議・通話 | 会議・通話に参加していた時間と、使っていたアプリ | 下の「会議・通話の判定」を参照 |
| ファイル編集 | 登録したフォルダの中で保存されたファイルのパス | フォルダの変更通知 |
| git コミット | あなた（`git config user.email` が一致する人）のコミット | 3 分おきに `git log` を確認 |
| git の取り込み | merge / pull / rebase をした時刻と内容 | 3 分おきに `git reflog` を確認 |
| メモ | `Ctrl+Alt+J` などで書いた一言 | そのまま |

### 会議・通話の判定

前面ウィンドウだけを見ると、Teams の会議に出ながら別のアプリで作業している時間が「別のアプリの作業」としか残りません。そこで、前面ウィンドウとは別に、次のどちらかを満たす間を「会議・通話」として並行して記録します。

- **マイクを使用中のアプリがある**: Windows がタスクバーにマイクのアイコンを出すときに使う情報を読んでいます。Teams・Zoom・ブラウザなど、どのアプリでも判定できます。音声そのものは一切扱いません
- **会議ウィンドウが開いている**: Zoom の会議ウィンドウ、Google Meet、Webex、Slack のハドルなど、会議中にしか現れないタイトルのウィンドウが、前面でなくても開いているとき

会議中はキー入力がなくても「無操作」にしません。話を聞いているだけで休んでいるわけではないからです。

> マイクをミュートにしていても、会議アプリがマイクを確保している間は「使用中」と判定されることが多いです。一方、ミュートで参加してマイクを一度も使わない会議や、聞くだけのウェビナーは判定できないことがあります。設定の「会議・通話を記録する」で無効にもできます。

### git 操作で変わったファイルは編集として数えない

`git merge` や `git pull`、ブランチの切り替えをすると、取り込んだファイルが作業フォルダに書き込まれます。これをそのまま「ファイル編集」として記録すると、**取り込んだだけのファイルを自分で編集したように見えて**しまいます。

そのため、ファイルの変更通知は数秒ためてから記録し、次のものは捨てています。

- 同じリポジトリで git が内部ファイル（`.git` の中の `index.lock`、`MERGE_HEAD` など）を書き換えた時刻の前後 5 秒以内の変更
- 一度に 40 ファイル以上が変わった変更（ブランチ切り替え、ビルド、フォーマッタの一括実行など）

コミットについては、次のように扱います。

- マージコミットは数えません
- rebase などで日付だけが新しくなった過去のコミットも数えません。「書かれた日時」が直近のものだけを数えます
- merge / pull / rebase の操作自体は「取り込み操作」として、別の種類で記録します

### 記録しないもの

- 画面の内容、キー入力、音声、クリップボード
- 除外キーワード（既定: password、1Password、InPrivate など）を含むウィンドウのタイトル。アプリ名も「(非公開)」になります
- 除外アプリに指定したアプリのウィンドウ
- 一時停止中の一切（画面の確認そのものを止めます）

## 2. 要約: AI に渡すテキストへの変換

記録をそのまま渡すと、細切れで量も多すぎます。そこで、1 日分を次のような**時系列のテキスト**に変換してから AI に渡しています。この変換はアプリの中で決まった規則どおりに行い、AI は使いません。

```
09:31–09:58 (27分) [Code] Board.tsx - kanban-app - Visual Studio Code
09:40 ファイル編集 「kanban-app」: src/components/Board.tsx
10:41–10:46 (5分) (キー・マウス操作なし)
11:00–11:45 (45分) 会議・通話に参加中 [Teams]（この間の前面ウィンドウと並行）
11:05–11:40 (35分) [chrome] Pull Request #131 - GitHub - Google Chrome
11:31 git commit 「kanban-app」 test: カラム並び替えのテストを追加
12:00–13:02 (62分) (画面ロック・スリープ＝離席)
15:00 git merge 「kanban-app」 merge feature: Merge made by the 'ort' strategy.（既存の変更の取り込み操作）
```

変換の規則:

- 同じウィンドウが 30 秒以内に続いたら 1 行にまとめ、15 秒未満の切り替えは省きます
- ファイル編集は 10 分ごと・フォルダごとにまとめます
- 「無操作」と「画面ロック」は別の言葉で書き分けます。単なる無操作を「離席」と書くと、AI が休憩と判断してしまうためです
- 記録中の `<` `>` は全角に置き換えます。ウィンドウタイトルに書かれた文章が AI への指示として扱われないようにするためです
- 設定で有効にしていれば、メールアドレス・URL のパス・API トークン・10 桁以上の番号をマスクします

実際に送られるテキストは、画面の「送信内容を確認」でそのまま見られます。

## 3. 推定: AI に何を判断させているか

### 作業ブロック（✦ AI で作業を整理）

AI に上のテキストを渡し、次の方針で「作業ブロック」に分けてもらいます。結果は決まった形式（開始・終了・タイトル・プロジェクト・分類・根拠）で受け取ります。

- 数分おきのアプリ切り替え（エディタ ↔ ブラウザ ↔ ターミナルなど）は、目的が同じなら 1 つにまとめる
- 1 ブロックはおおむね 15 分〜2 時間
- ファイル編集・コミット・メモを作業の強い根拠とし、根拠が薄いものは「その他」にする

分類は次の 11 種類です。

| 分類 | 表示名 | 分類 | 表示名 |
|---|---|---|---|
| coding | 実装 | meeting | 会議 |
| review | レビュー | communication | 連絡 |
| debugging | デバッグ | design | 設計 |
| research | 調査 | admin | 事務 |
| writing | 執筆 | break | 休憩 |
| | | other | その他 |

「会議」「休憩」は誤りやすいので、次のように扱いを決めています。

- **会議**: 「会議・通話に参加中」の時間は会議とします。その間に別のアプリを使っていれば、会議に出ながらの作業として根拠に書きます
- **休憩**: 休んでいたと言える時間だけに使います
  - 画面ロック・スリープの時間
  - 前後の作業ともつながらない長い無操作（目安 30 分以上）
  - 昼休みの時間帯の長い無操作

  短い無操作や作業の合間の無操作は、資料を読む・画面共有を見る・考えるといった作業の一部として扱います

AI が「休憩」と判断したブロックは、アプリでも記録と照らし合わせます。その時間の半分以上で会議・通話していれば「会議」に、半分以上でウィンドウを操作していれば「その他」に置き換えます。AI の読み違いが 1 か所あっても、1 日の見え方が大きく崩れないようにするためです。

### 日報（✦ 日報を生成）

タイムライン、作業ブロック（整理済みの場合）、日報テンプレートを渡し、本人の視点で下書きを書いてもらいます。

- コミット・ファイル・メモから読み取れる具体的な成果を優先します
- 記録から読み取れないことは書かず、「（要確認）」と残して本人が埋められるようにします
- git の取り込み操作は「取り込んだ」と書き、取り込んだ内容を自分の成果としては扱いません

### 足跡に聞く

AI は次の 3 つの道具を使い、必要な日の記録だけを読んで答えます。どの道具を使ったかは、回答の上にチップで表示されます。

| 道具 | できること |
|---|---|
| `list_days` | 記録がある日の一覧と、各日のアクティブ時間を見る |
| `get_day` | 指定した日のタイムライン（整理済みなら作業ブロック・日報も）を読む |
| `search_events` | ウィンドウタイトル・ファイル・コミット・会議・メモをキーワードで探す |

ツール呼び出しに対応していないローカル LLM では、直近 7 日分のタイムラインをまとめて渡して答えさせます。

## 推定を外しやすい場面

| 場面 | 起きること | 対策 |
|---|---|---|
| 紙の資料を読む、対面で打ち合わせる | PC の操作がないので「無操作」になる | メモを残すと AI が理由を読み取れます（例:「設計レビュー（対面）」） |
| ミュートのまま聞くだけの会議 | 会議と判定できないことがある | メモを残すか、会議ウィンドウを開いておく |
| 1 つのウィンドウで複数の作業（ブラウザのタブなど） | タブを切り替えるとタイトルは変わるが、目的までは分からない | タイトルから推測するので、ある程度は分けられます |
| 登録していないフォルダでの作業 | ファイル編集・コミットが記録されない | 設定の「記録するフォルダ」に追加する |
| リモートデスクトップ・仮想マシンの中の作業 | 接続ソフトのウィンドウとしか見えない | メモで補う |

分類が実態と違うときは、作業ブロックを作り直す（✦ AI で作業を整理）か、日報を「編集」で直してください。
